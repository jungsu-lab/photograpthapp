# FrameFit Android 실기기 검증 체크리스트

이 문서는 실제 사진을 사용한 최종 검증 기록용이다. 개인 사진·화면 캡처·파일 경로는
저장소에 커밋하지 않는다. 자동 테스트용 fixture가 필요하면 저작권과 사용 권한이 분명한
작은 이미지 또는 생성한 이미지만 사용한다.

## 사전 조건

- Windows 개발 환경에서는 Flutter 플러그인 빌드를 위해 Developer Mode를 켠다.
- Android 빌드용 JDK 17 이상을 설치하고 `JAVA_HOME`을 설정한다.
- Android 7.0(API 24) 이상 실기기를 USB 디버깅으로 연결한다.
- 최초 설치 전 앱의 카메라/사진 권한을 초기화한다.
- JPEG, PNG, 세로 EXIF JPEG, 12MP 이상 JPEG를 준비한다.

## 핵심 완주 흐름

- [x] 앱 실행 후 `사진 불러오기`를 탭해 JPEG 한 장을 선택한다.
- [x] 기본 보정·일본 여행·촬영 효과·흑백 카테고리의 12개 프리셋이 보인다.
- [ ] 프리셋을 탭했을 때 실제 사진 미리보기가 바뀌고, 강도 0은 원본과 동일하다.
- [ ] 강도 100과 수동 조정(노출·대비·색온도 등)이 즉시 새 미리보기에 반영된다.
- [ ] `자르기`에서 원본·1:1·4:5·16:9의 중앙 비율 자르기가 미리보기와 내보내기에 동일하게 적용된다.
- [x] 사진을 길게 눌러 원본을 확인하고 손을 떼면 결과가 복원된다.
- [ ] `초기화` 후 원본 상태로 돌아간다.
- [x] `내보내기`에서 사진첩 저장 후 FrameFit 앨범의 결과를 갤러리에서 연다.
- [ ] 같은 결과를 시스템 공유 창으로 전달하고 대상 앱에서 정상 표시되는지 확인한다.
- [ ] 원본 파일의 픽셀이 바뀌지 않았으며, 새 JPEG/PNG에 위치정보가 복사되지 않았는지 확인한다.

## 입력, 권한, 오류

- [x] 카메라로 전면/후면 사진을 각각 촬영하고 편집기로 이동한다.
- [ ] 세로 EXIF JPEG가 올바른 방향으로 표시된다.
- [ ] 투명 PNG 입력이 열리고 PNG로 저장되며 투명도가 유지된다.
- [ ] 사진 선택 취소, 카메라 권한 거부, 영구 거부 후 설정 이동 안내가 안전하게 표시된다.
- [ ] 이미지가 아닌 파일 또는 손상 파일은 이해 가능한 오류를 보이고 앱이 종료되지 않는다.
- [ ] 저장 중 앱을 백그라운드로 보냈다가 돌아와도 중복 내보내기나 멈춤이 없다.

## 성능 및 접근성 기록

실기기·Android 버전·이미지 해상도·미리보기 시간·12MP 내보내기 시간을 아래 표에
기록한다. 목표는 미리보기 0.3~0.8초, 12MP JPEG 내보내기 8초 이내이며, 수치를
억지로 맞추기보다 병목과 관찰 결과를 남긴다.

| 기기 / Android | 입력 이미지 | 미리보기 | 내보내기 | 결과 / 문제 |
| --- | --- | --- | --- | --- |
| Galaxy S23 (SM-S916N) / Android 16 | 945×2048 PNG | 정상, 실제 프리셋 썸네일 생성 확인 | 정상 | FrameFit 앨범 저장 및 시스템 공유 창 호출 확인 (2026-07-15) |
| Galaxy S23 (SM-S916N) / Android 16 | 3000×4000 JPEG (12MP) | 편집기 진입 약 3.9초 | 내보내기 준비 약 4.2초 | 메모리 오류 없이 프리셋 적용·원본 해상도 렌더링 확인 (2026-07-15) |

현재 실기기에서 PNG 선택, 프리셋 적용, 강도 50%, 길게 눌러 원본 비교, 원본 해상도
PNG 생성, FrameFit 앨범 저장, 시스템 공유 창 호출, 전면·후면 카메라 촬영 후 편집기
진입, 12MP JPEG 선택과 원본 해상도 렌더링까지 확인했다. EXIF 방향은 픽셀 처리 자동
테스트로 검증했다. 갤러리의 실제 세로 EXIF 사진과 권한 거부 시나리오는 아직 별도로
검증해야 한다.

- [ ] 360×800, 390×844, 412×915 화면과 텍스트 크기 130%에서 주요 버튼을 확인한다.
- [ ] 선택 상태가 색상만으로 표현되지 않고, 모든 핵심 버튼에 접근 가능한 이름이 있다.
